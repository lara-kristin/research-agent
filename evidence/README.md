# Evidence of Execution

Execution and testing evidence for the research agent, in the order it was
captured.

The stage in a filename records when a behaviour was built, not which stage of
the design it satisfies. Build order followed risk rather than the runtime
sequence, so some behaviours were implemented earlier than their place in the
stage plan: 23a and 23b evidence the query reformulation belonging to stage 5,
and 26 evidences the evidence review belonging to stage 5.

Screenshots evidence the behaviour of the live services. Conditions those
services do not produce on demand, such as a response missing its `total`
field, a `data` field of the wrong type, or a record with no title, are
covered by unit tests rather than by contrived captures.

| 24_stage2_response_cache_hit_and_bypass.png | The response cache and its bypass, on the same query seconds apart. The second, with the cache bypassed, issues a live request that is rate limited and recovered by retry. A cached run and a live run are therefore distinguishable in the log, which is what allows the cache to be used during development without misrepresenting a run as live |
